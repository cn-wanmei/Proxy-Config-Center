# 架构说明 / Architecture Overview

## 中文

本仓库采用 **Core First + IR + Capability + Adapter + Artifact** 架构。

### 分层

- `core/`：唯一业务语义来源，维护规则、DNS、策略组、服务与优先级
- `scripts/ir.py`：把 Core 编译为平台无关的 `ResolvedIR`
- `scripts/engines/`：负责 capability、rule source、reference 等编译期约束
- `platforms/`：平台 capability 与 renderer，只负责平台表达
- `build/`：本地/CI 临时生成目录，不作为稳定源码接口
- GitHub Actions：验证、构建、结构检查并发布 Artifact
- GitHub Release：发布六端正式配置

### 编译链

```text
Core
 ↓
Schema / Semantic Validation
 ↓
Reference Graph
 ↓
Resolved IR
 ↓
Capability Engine
 ↓
Platform Adapter / Renderer
 ↓
6 platform configs
 ↓
Golden + Structural Check
 ↓
Artifact / Release
```

### Capability 原则

`rule_set`、`rule_provider`、`domain_fallback` 是三个独立能力。Core 不判断平台名称；平台差异通过 capability profile 与 adapter 表达。

### 发布原则

生成配置不回写 `main`。同一套 CI 从源码生成 Artifact，正式 Release 使用同一构建结果，避免源码、构建物和发布物漂移。

### 节点

**节点由 Sub-Store 独立管理**，本仓库不承担节点订阅的长期存储与生命周期。

---

## English

The repository uses a **Core First + IR + Capability + Adapter + Artifact** architecture.

- `core/` is the single source of business semantics.
- `scripts/ir.py` compiles Core into platform-neutral `ResolvedIR`.
- `scripts/engines/` enforces compile-time capability, rule-source and reference constraints.
- `platforms/` contains platform capability profiles and renderers.
- `build/` is generated output, not a source-of-truth directory.
- GitHub Actions validates, builds and publishes artifacts.
- GitHub Releases distribute the six final platform configurations.

New clients should normally require only a new adapter and capability profile, not Core changes.
