# 分流质量体系

当前 v1.1.x 采用以下质量闭环：

```text
Rule Source
  ↓
Priority
  ↓
Rule Audit
  ├─ duplicate
  ├─ conflict
  ├─ unreachable
  └─ invalid target
  ↓
Rule → Strategy Group Index
  ↓
Hit Trace
  ↓
Semantic IR
  ↓
7-platform semantic equivalence
```

## Rule → Strategy Group 索引

`make audit` 生成：

- `build/audit/rule-strategy-index.json`：机器读取
- `build/audit/rule-strategy-index.md`：人工审计

索引同时记录 AI Provider Registry，避免 AI 规则只能从散落的 YAML 中推断。

## 规则解释

```bash
make trace DOMAIN=chatgpt.com
```

解释内容包括首个命中策略组、优先级、规则类型、模式、来源，以及被更高优先级规则选择后不会生效的候选规则。

未知域名明确报告 `final` fallback，不伪造具体业务命中。

## AI Provider Registry

`core/ai/providers.yaml` 是 AI 服务的语义目录。它描述：

- provider ID
- AI 子类别
- 目标策略组
- 官方域名集合

当前规则 YAML 仍是实际渲染输入；Registry 作为覆盖约束和审计索引，避免把 Registry 当成未经验证的远程规则源。

## 平台语义

七端不要求文本格式一致，而要求以下语义一致：

- service strategy target
- final fallback
- rule source target
- proxy group target

平台可以使用各自原生语法表达同一语义。

## 路径卫生

CI 禁止在 scripts/tests 中重新引入 `sys.path.insert` 或 `sys.path.append`。统一入口使用 `PYTHONPATH` / Makefile。
